# Googleサービス連携 予約受付自動化ツール

Googleフォームで予約が届くと、Googleカレンダーへの予定登録・予約者への予約完了メール送信・処理結果の記録までを自動で行うツールです（Google Forms / Sheets / Apps Script / Calendar / Gmail）。

[作品一覧](https://github.com/moedaichi0629-ai/landing-page) · [ポートフォリオ](https://moedaichi0629-ai.github.io/)

> **このリポジトリについて**
> 受託開発を想定して制作した**ポートフォリオ用の模擬案件（デモ）**です。実在のクライアント・実案件ではなく、「Googleフォームでオンライン相談の予約を受け付ける小規模事業者」を想定し、要件定義から実装・実機確認・納品資料の作成までを一貫して行いました。

## 作業前 → 作業後

| | 作業前（想定） | 作業後 |
|---|---|---|
| カレンダー登録 | 予約が届くたびに、回答を見ながら手作業で予定を作成 | フォーム送信と同時に60分の予定を自動登録 |
| 予約確認メール | 予約者ごとに手作業でメールを作成・送信 | 予約完了メールを自動送信 |
| 処理状況の管理 | 「登録したか」「メールを送ったか」を記憶やメモで管理 | スプレッドシートの各行に処理ステータス・送信日時・エラー内容を自動記録 |
| エラー時の対応 | どこで失敗したか分かりにくい | エラー内容を確認し、メニューから選択した予約だけ再実行 |

## 主な機能

- **フォーム回答の自動記録**：予約内容はGoogleフォームの標準機能でスプレッドシートに保存
- **カレンダーへの自動登録**：予約日時から60分の予定を作成（予定名・相談内容・メールアドレスを登録）
- **予約完了メールの自動送信**：予約者へGmailで予約日時入りの完了メールを送信
- **処理結果の記録**：処理ステータス・CalendarイベントID・メール送信日時・エラー内容をシートに記録
- **入力不足・過去日時のチェック**：不備のある予約はカレンダー登録・メール送信を行わずエラーとして記録
- **選択した予約の手動再実行**：エラーになった予約をメニューから再処理（カレンダー予定は二重作成しない）

## 処理の流れ

```
Googleフォーム（予約送信）
   ↓
Googleスプレッドシート（回答が1行追加される）
   ↓
Google Apps Script（フォーム送信時トリガー）
   ├─ 入力チェック（必須項目・予約日時・過去日時）
   ├─ Googleカレンダー：60分の予定を登録
   ├─ Gmail：予約完了メールを送信
   └─ スプレッドシート：処理結果をG〜J列へ記録
```

## 使用技術

- Google Forms
- Google Sheets
- Google Apps Script
- Google Calendar
- Gmail

追加の有料サービス・外部サーバーは使用していません。APIキー・トークン等の秘密情報も使用していません（Googleアカウントの権限承認のみで動作します）。

## セットアップ

1. **フォームとSheetsの連携**: Googleフォームの「回答」タブから回答先スプレッドシートを作成・連携します（Googleフォームの標準機能）。フォームの項目は「お名前・メールアドレス・予約日・予約時間・相談内容」の順にします（A〜F列に対応）。
2. **Code.gsの配置**: 回答先スプレッドシートで「拡張機能 > Apps Script」を開き、コンテナバインドスクリプトとして `gas/Code.gs` の内容を配置します。
3. **タイムゾーン（Asia/Tokyo）**: スプレッドシートの「ファイル > 設定」と、Apps Scriptプロジェクトのタイムゾーンを両方ともAsia/Tokyoに設定します。コード内の日時計算（`buildReservationDateTime` 等）もAsia/Tokyo前提で実装されています。
4. **インストール型「フォーム送信時」トリガー**: Apps Scriptエディタの「トリガー」画面から、イベントのソース「スプレッドシートから」、イベントの種類「フォーム送信時」、実行する関数 `onFormSubmit` を指定してトリガーを追加します。`onFormSubmit` は送信された行を特定し、共通処理関数 `processReservationRow` を呼び出します。
5. **初回のGoogle権限承認**: 初回実行時、Calendar・Gmail・Sheetsへのアクセス権限を求める承認画面が表示されます。スクリプトを実行するGoogleアカウントで承認してください。

## 使い方

1. 予約者がGoogleフォームから予約を送信する
2. 自動でカレンダー登録・予約完了メール送信まで完了する（通常は管理者の操作は不要）
3. スプレッドシートのG列（処理ステータス）で結果を確認する
4. 「エラー」「Calendar登録済み・メール未送信」の行があれば、J列でエラー内容を確認し、その行を選択して「予約管理 → 選択した予約を再実行」を実行する

運用担当者向けの操作説明は [docs/06_delivery.md](docs/06_delivery.md)、確定要件は [docs/02_requirements.md](docs/02_requirements.md) にまとめています。

<details>
<summary>通常の動作（関数レベル）</summary>

1. お客様がGoogleフォームから予約を送信する
2. フォームの回答がスプレッドシートに1行追加される（Googleフォームの標準機能）
3. インストール型トリガーにより `onFormSubmit` が呼び出される
4. `processReservationRow` が対象行を処理する
   - お名前・メールアドレス・予約日・予約時間・相談内容を取得する
   - D列（予約日）・E列（予約時間）から予約開始日時（Asia/Tokyo）を生成する
   - 過去日時でなければ、デフォルトCalendarへ60分の予定を登録し、イベントIDをH列へ保存する
   - 予約者へ予約完了メールを送信する
   - 処理結果をG〜J列へ記録する

</details>

<details>
<summary>手動再実行</summary>

Google Sheets上で対象の予約行（データ行）を選択し、以下のカスタムメニューから再実行します。

```
予約管理
→ 選択した予約を再実行
```

- 選択行が1行目（ヘッダー行）の場合、または選択行にお名前が入力されていない場合は処理を行わず、アラートを表示します。
- H列にCalendarイベントIDが既に存在する場合、新しいCalendar予定は作成しません。これにより同じフォーム回答に対するCalendarの二重作成を防ぎます。
- 予約完了メールの送信はH列・I列の値に関係なく再実行されます。そのため「完了」の行を再実行すると、予約完了メールが再送信されます。再実行は「エラー」「Calendar登録済み・メール未送信」の行に対して行う想定です。
- 手動再実行は、フォーム送信時と同じ `processReservationRow` を呼び出す実装になっており、処理ロジックの重複はありません。

</details>

<details>
<summary>エラー処理</summary>

`gas/Code.gs` の実装に基づく整理です。

| ケース | 条件 | G列 | H列 | I列 | J列 |
|---|---|---|---|---|---|
| 入力不足 | お名前・メールアドレス・予約日・予約時間・相談内容のいずれかが空 | エラー | 空欄 | 空欄 | エラー内容 |
| 日時の解析失敗 | 予約日・予約時間が想定形式（予約時間は「時:分」の24時間形式）でない | エラー | 空欄 | 空欄 | エラー内容 |
| 過去日時 | 予約日＋予約時間が処理時点以前（Calendar未登録の行のみ判定） | エラー | 空欄 | 空欄 | エラー内容 |
| Calendar登録失敗 | Calendar登録処理自体が失敗 | エラー | 空欄 | 空欄 | エラー内容 |
| メール送信失敗 | Calendar登録成功後、メール送信が失敗 | Calendar登録済み・メール未送信 | イベントID | 空欄 | エラー内容 |

いずれのエラーでも管理者への通知メールは送信しません（`docs/02_requirements.md` 10章の確定仕様）。

</details>

<details>
<summary>注意事項</summary>

- Calendar登録先は、GASを実行・認可したGoogleアカウントのデフォルトカレンダーです（共有カレンダー等は対象外）。
- 過去日時判定は、Calendar未登録の行（H列が空の行）に対してのみ行われます。既にCalendar登録済みの行（H列にイベントIDがある行）を再実行する場合は、この判定を行わずメール送信のみ試行します（`gas/Code.gs` の `processReservationRow` 内コメント参照）。この挙動は `docs/02_requirements.md` に直接の記載はなく、実装判断です。
- 同じ内容のフォーム回答が複数回送信された場合も、それぞれ別の予約として処理されます（重複チェックは行いません）。同日時の複数予約も許可されます。
- 相談内容・お名前に含まれる改行や記号は、変換せずそのまま文字列として扱われます。
- 秘密情報（APIキー・トークン等）はコードに記載していません。

</details>
