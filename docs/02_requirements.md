# 02_requirements.md

「Googleサービス連携 予約受付自動化ツール」確定要件

- 作成日: 2026-09-20
- 最終更新日: 2026-09-20
- ステータス: 仕様確定（未確定事項なし／実装未着手）

---

## 1. プロジェクト概要

Googleフォームからオンライン相談の予約を受け付け、フォーム送信をトリガーに以下を自動化する。

- Google Calendarへの予定登録
- Gmailによる予約完了メールの送信

## 2. 現状の課題

現在は予約が入るたびに担当者がスプレッドシートを確認し、Google Calendarへの予定登録とお客様へのメール送信を手作業で行っている。

## 3. 目的

Googleフォーム送信後に発生する定型作業（Calendar登録・メール送信）を自動化し、手作業を排除する。

## 4. スコープ

### 4.1 対応する

- フォーム送信をトリガーとしたSheetsへのデータ保存（フォーム標準機能）
- Calendarへの予定登録
- Gmailでの予約完了メール送信
- 過去日時の予約に対するエラー処理
- Calendar登録・メール送信の処理結果／エラー内容のSheets記録
- 同一フォーム回答（同一行）の二重処理防止（再実行時の重複登録防止）

### 4.2 スコープ外（今回は対応しない）

- 予約の重複防止（同日時への複数予約はブロックしない。許可する）
- 予約可能枠の管理（空き枠の提示・制御）
- 予約変更機能
- キャンセル機能
- Google Meet等のオンライン会議URLの自動発行
- 管理者へのエラー通知メール送信
- 外部有料サービスの利用
- 自動リトライ（エラー時の自動再実行）

## 5. 実行環境・トリガー・タイムゾーン仕様

### 5.1 実行環境

Googleフォームの回答先Google Sheetsに紐づけたGoogle Apps Script（コンテナバインドスクリプト）で処理を実装する。

### 5.2 トリガー

インストール型の「フォーム送信時」トリガーを設定し、フォーム送信をトリガーとして予約処理（Calendar登録・メール送信）を実行する。

### 5.3 タイムゾーン

- 日本時間（Asia/Tokyo）を前提とする。
- スプレッドシートおよびGoogle Apps Scriptのタイムゾーン設定も日本時間に統一する。

## 6. Googleフォーム仕様

### 6.1 フォーム名

オンライン相談 予約フォーム

### 6.2 入力項目

| 項目名 | 種別 |
|---|---|
| お名前 | 記述式 |
| メールアドレス | 記述式 |
| 予約日 | 日付 |
| 予約時間 | プルダウン |
| 相談内容 | 記述式 |

### 6.3 予約時間の選択肢（プルダウン）

- 10:00
- 11:00
- 13:00
- 14:00
- 15:00

### 6.4 予約条件

- 相談時間は60分固定
- 想定件数: 1日1〜5件程度、月30〜50件程度
- 同じ日時への複数予約を許可する（重複防止は行わない）
- 同一内容の複数送信の扱いは「12. データの扱い」を参照

## 7. Google Sheets仕様

### 7.1 スプレッドシート名

オンライン相談 予約管理

### 7.2 列構成

| 列 | 項目名 | 内容 |
|---|---|---|
| A | タイムスタンプ | フォーム送信日時（フォーム標準機能により自動記録） |
| B | お名前 | フォーム回答値 |
| C | メールアドレス | フォーム回答値 |
| D | 予約日 | フォーム回答値 |
| E | 予約時間 | フォーム回答値 |
| F | 相談内容 | フォーム回答値 |
| G | 処理ステータス | 処理結果を記録する自動化側の書き込み列（値は7.3参照） |
| H | CalendarイベントID | 登録したCalendarイベントのID（再実行時の二重登録防止に使用） |
| I | メール送信日時 | 予約完了メールを送信した日時 |
| J | エラー内容 | 処理中に発生したエラーの内容 |

### 7.3 処理ステータス（G列）の値

G列では以下4状態を扱う。

| 値 | 意味 |
|---|---|
| 処理中 | 予約処理を実行中であることを示す状態 |
| 完了 | Calendar登録・メール送信の両方が正常に完了した状態 |
| エラー | 過去日時判定によるエラー、またはCalendar登録処理自体の失敗等、処理が完了しなかった状態 |
| Calendar登録済み・メール未送信 | Calendar登録は成功したが、メール送信が未完了の状態（再実行対象） |

### 7.4 ケース別の列値パターン

| ケース | G（処理ステータス） | H（CalendarイベントID） | I（メール送信日時） | J（エラー内容） |
|---|---|---|---|---|
| 処理成功時（Calendar登録・メール送信とも成功） | 完了 | CalendarイベントID | メール送信日時 | 空欄 |
| Calendar登録後、メール送信が失敗した場合 | Calendar登録済み・メール未送信 | 作成済みCalendarイベントID | 空欄 | メール送信時のエラー内容 |

上記以外のエラーケース（過去日時判定、Calendar登録自体の失敗等）は「10. エラー処理仕様」の記載に従う。

## 8. Calendar処理仕様

フォーム送信後、GASを実行・認可するGoogleアカウントのデフォルトCalendarへ予定を登録する。

| 項目 | 内容 |
|---|---|
| 予定名 | 「〇〇様 オンライン相談」（〇〇はフォームの「お名前」） |
| 開始日時 | フォームで選択された予約日・予約時間（Asia/Tokyo） |
| 終了日時 | 開始時刻から60分後 |
| 説明欄 | 相談内容、お客様のメールアドレスを含める |

## 9. Gmail処理仕様

Calendar登録後、お客様へ予約完了メールを送信する。

### 9.1 送信元

- メールはGASを実行・認可するGoogleアカウントから送信する。
- 差出人名を変更する特別な処理は行わない。

### 9.2 件名

【オンライン相談】ご予約ありがとうございます

### 9.3 本文に含める項目

- お客様の名前
- 予約日
- 予約開始時間

オンライン相談用URLは本文に記載しない（スコープ外のため）。

### 9.4 本文テンプレート（基本形）

```
〇〇様

ご予約ありがとうございます。
〇月〇日 HH:mmより、オンライン相談のご予約を承りました。

よろしくお願いいたします。
```

（〇〇＝お名前、〇月〇日＝予約日、HH:mm＝予約開始時間）

## 10. エラー処理仕様

### 10.1 過去日時判定

- 予約日単独ではなく、「予約日＋予約時間」から予約日時（Asia/Tokyo）を生成して判定する。
- 生成した予約日時が処理時点以前の場合は「過去」として扱う。
- 過去と判定された場合:
  - Calendarへ登録しない
  - メールを送信しない
  - Sheetsへエラーとして記録する（G列: エラー、J列: エラー内容）

### 10.2 Calendar登録またはメール送信でエラーが発生した場合

- Sheetsへ処理状況（G列）とエラー内容（J列）を記録する
- 管理者への通知メールは送信しない

## 11. 再実行仕様

### 11.1 基本方針

- 今回は自動リトライを実装しない。
- エラーが発生した予約について、管理者が手動で再実行できる方式とする。
- Calendar作成後、イベントIDをSheets（H列）へ保存する。
- 再実行時、対象行のH列（CalendarイベントID）に値が存在する場合は、新しいCalendar予定を作成せず、未完了の処理（メール送信等）のみ再実行する。
- これは同日時の別予約を禁止する機能ではなく、同じフォーム回答（同一行）に対する二重処理（Calendarの二重作成）を防ぐための仕様である。

### 11.2 手動再実行の操作方法

Google Sheetsのカスタムメニューから、現在選択している予約行を手動再実行できる方式とする。

メニュー構成:

```
予約管理
└─ 選択した予約を再実行
```

### 11.3 再実行時の処理内容

- 選択行の予約データを対象とする。
- H列にCalendarイベントIDが存在する場合、Calendar予定を新規作成しない。
- 未完了の処理のみ再実行する。
- 正常完了した場合はステータスを「完了」にする（列値は7.4「処理成功時」を参照）。
- エラー発生時はステータスとエラー内容を更新する（列値は7.4「Calendar登録後、メール送信が失敗した場合」または該当するエラー内容に従う）。

### 11.4 Calendar登録済み予約の再実行

H列にCalendarイベントIDが存在する場合は、Calendarへの登録がすでに完了している予約として扱う。

この場合:

- Calendar予定を新規作成しない
- 過去日時判定によって再実行を停止しない
- 未完了の処理のみ再実行する

たとえばCalendar登録後にメール送信のみ失敗し、後日再実行した場合でも、予約日時がすでに過去になっていることを理由にメール再送処理を停止しない。

これは新規予約に対する過去日時許可ではなく、Calendar登録済み予約の未完了処理を復旧するための仕様とする。

新規予約（H列にCalendarイベントIDがない場合）は、従来どおり予約日時が処理時点以前ならエラーとする（10.1参照）。

## 12. データの扱い

### 12.1 特殊文字

相談内容・お名前等に含まれる一般的な改行・記号は、エスケープや変換を行わず、文字列としてそのまま扱う（Calendar説明欄、メール本文、Sheets記録のいずれにおいても同様）。

### 12.2 同一内容の複数送信

- 同じ名前・メールアドレス・予約日時・相談内容であっても、別々にフォーム送信された回答はそれぞれ別の予約として処理する（Calendar登録・メール送信をそれぞれ実施する）。
- 同日時の複数予約も許可する（重複防止・排他制御は行わない）。
- 再実行時の二重処理防止（H列のCalendarイベントIDによる判定）は、あくまで「同一行（同一フォーム回答）」に対する再実行時のみに適用され、別行（別回答）には影響しない。

## 13. 技術方針

使用するサービス:

- Googleフォーム
- Google Sheets
- Google Apps Script
- Google Calendar
- Gmail

追加の有料サービス・外部サーバーは使用しない。

## 14. セキュリティ方針

- 秘密情報（APIキー、認証情報等）をコードへ直接記載しない
- 必要以上の権限・外部サービスを使用しない

## 15. 受け入れ基準（Acceptance Criteria）

以下をすべて満たした場合に完成とする。

1. フォーム回答がSheetsへ保存される
2. 正常な未来日時であれば60分のCalendar予定が作成される
3. Calendarの予定タイトル・説明欄が仕様通りである
4. 予約完了メールが送信される
5. 過去日時（予約日＋予約時間が処理時点以前）の場合、Calendar登録・メール送信のいずれも行われない
6. エラー内容をSheets上で確認できる
7. Calendar登録後にメール送信のみ失敗した場合、再実行してもCalendar予定が二重作成されない
8. 同日時の別予約（別回答）はそれぞれ登録できる
