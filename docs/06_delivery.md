# 06_delivery.md

「オンライン相談 予約受付自動化ツール」納品・操作説明資料

- 作成日: 2026-09-20

---

## 1. 納品内容

今回、以下の自動化の仕組みを実装しました。

- お客様がGoogleフォームで送信した予約内容を、自動でGoogleカレンダーに登録します
- カレンダー登録に合わせて、お客様へ「予約完了メール」を自動で送信します
- 処理がうまくいったか、エラーになったかを、スプレッドシート上で確認できるようにしました
- エラーが発生した予約について、スプレッドシートの操作だけで手動でやり直せるようにしました
- 同じ予約を誤ってカレンダーに二重登録しない仕組みを組み込みました

## 2. 基本的な使い方

基本的な流れは以下の通りです。

```
お客様がGoogleフォームから予約
　↓
自動処理（カレンダー登録・メール送信）
　↓
Googleカレンダーに予定が登録される
　↓
お客様へ予約完了メールが自動送信される
```

通常の予約であれば、管理者による操作は不要です。お客様がフォームを送信した時点で、カレンダー登録とメール送信まで自動的に完了します。

## 3. スプレッドシートの見方

予約管理用のスプレッドシートには、処理結果を確認するための列があります。

| 列 | 内容 |
|---|---|
| G：処理ステータス | その予約の処理結果です。「完了」「エラー」「Calendar登録済み・メール未送信」「処理中」のいずれかが表示されます。 |
| H：CalendarイベントID | カレンダーに登録された予定を識別するIDです。この列に値が入っていれば、カレンダーへの登録は完了しています。 |
| I：メール送信日時 | 予約完了メールを送信した日時です。メールが送信できていない場合は空欄になります。 |
| J：エラー内容 | 処理中に問題が発生した場合、その内容がここに表示されます。正常に完了している場合は空欄です。 |

## 4. エラーが発生した場合

G列が「エラー」または「Calendar登録済み・メール未送信」になっている場合は、J列でエラーの内容を確認できます。

内容を確認のうえ、必要であれば以下の手順で再実行してください。

1. 対象の予約の行（1行全体でなく、その行のいずれかのセル）を選択する
2. スプレッドシート上部のメニューから、次の順に選択する

```
予約管理
→ 選択した予約を再実行
```

すでにカレンダー登録が済んでいる予約（H列にIDが入っている予約）を再実行しても、カレンダーに予定が二重に登録されることはありません。未完了の処理（メール送信など）のみが再実行されます。

## 5. 運用上の注意

- フォームの項目名や、スプレッドシートの列構成（A〜J列）は変更しないでください。仕組みが特定の列位置・項目名を前提に動作しているため、変更すると正しく動作しなくなるおそれがあります。
- GAS（Google Apps Script）のコードは、開発担当者以外は変更しないでください。
- 設定済みのトリガー（フォーム送信をきっかけに処理を動かす設定）を削除しないでください。削除すると、フォーム送信後の自動処理（カレンダー登録・メール送信）が行われなくなります（フォームの回答自体は、この設定と関係なくスプレッドシートに記録され続けます）。
- Googleカレンダー・Gmailに関する権限設定（アクセス権の取り消しなど）を変更すると、自動処理が正しく動作しなくなるおそれがあります。
- フォームの「予約時間」の選択肢（10:00、11:00など）を変更・追加する場合は、必ず「時:分」の24時間形式（例：16:00）で統一してください。この形式と異なる入力になると、日時の読み取りに失敗し、エラーとして記録されます。

## 6. 今回含まれない機能

以下の機能は、今回のご依頼の範囲には含まれていません。

- 同じ日時・同じ内容の予約が重なった場合に自動でブロックする機能（同日時の複数予約は、それぞれ登録されます）
- 予約可能な日時の枠を管理する機能（空き状況の表示・制限）
- 予約内容の変更・キャンセル機能
- オンライン会議用URL（Google Meetなど）の自動発行
- エラー発生時に管理者へ通知メールを送る機能
- エラー発生時に自動で処理をやり直す機能（現在は手動での再実行のみ対応）
- 有料の外部サービスとの連携

## 7. 動作確認結果

実際の環境（実機）で確認した内容と、今回のテストで確認できた内容を分けて記載します。

### 実機で確認済み

- Googleフォームからスプレッドシートへの自動反映
- 正常な予約でのカレンダー登録
- カレンダー予定が60分で登録されること
- 予約完了メールの送信
- 処理結果のスプレッドシートへの記録
- 過去日時の予約がエラーとして記録されること
- 過去日時の予約でカレンダー登録・メール送信が行われないこと
- 完了済みの予約を再実行しても、カレンダーが二重登録されないこと
- 完了済みの予約を再実行しても、メールが二重送信されないこと
- 同じ日時の別々の予約が、それぞれ登録されること

### テスト環境（モック）でのみ確認済み・実機での確認が未実施

- カレンダー登録に成功した後、メール送信だけ失敗した状態からの再実行（開発時のテスト環境では正しく動作することを確認していますが、実際のGoogle環境での障害発生時の動作確認はまだ行っていません）
